# Reference data

## `analytical/`: numerical verification, not validation
Closed-form references generated by `tools/make_reference_fixtures.py`:

* `layered_viscosity_wide_*`: two layers with viscosity ratios 0.25, 1 and 4 in a wide channel
  (W = 12 H), compared with the layered plane-Poiseuille interface over the central half of the
  width. The ratio-0.25 family is held out.
* `lateral_layers_equal`: three side-by-side layers with flow ratio 1:2:3, compared with the
  exact duct series.

Run with `crossflow validate-references reference_data/analytical`.

## `legacy_baseline/`: legacy behaviour, not truth
Label arrays and timings of the frozen legacy solver for the shared-capability examples. Tests use them to
detect accidental changes in how the archived code is executed.

## Adding external references (`crossflow-reference/1`)
Each case is `<name>.json` (metadata) plus `<name>.npz` (arrays); see `src/crossflow_simulator/calibration.py`.
Required metadata:

* `source`: `kind` (`cfd` | `experiment` | `analytical` | `numerical_self`), `tool`, `citation`,
  `license`, `reuse_permitted`
* `config`: the physical case as a project file
* `plane`: `x_m` and a description
* `quantity`: `labels` or `interface`
* `orientation`
* `family`: train/holdout splits keep whole families together
* `numerics`: mesh convergence for CFD, registration for experiments
* optional `uncertainty.interface_m`

Label arrays use the project's stream codes on a cell-centred grid (`y_edges_m`, `z_edges_m`).
Only `cfd` and `experiment` sources count as external validation. Keep large datasets outside the
repository and store only metadata and small fixtures here.
